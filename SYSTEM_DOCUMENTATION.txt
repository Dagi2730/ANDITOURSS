1. SYSTEM OVERVIEW & ARCHITECTURE
===============================================================================
ANDI TOURS is a full-stack web application designed for booking, managing, and 
exploring tour packages across Ethiopia. It provides a dual-facing interface:

  A. Customer-Facing Web Portal:
     - Allows tourists to browse destinations, view rich tour details, inspect 
       photo galleries with multi-image carousels, book tours with passport 
       document uploads, submit guest photo stories, view verified traveler 
       reviews, and manage their bookings under a dedicated "My Account" area.

  B. Admin Control Center (/admin):
     - Provides administrative tools to monitor live statistics (Total Users, 
       Total Bookings, Active Packages), manage tour packages (CRUD with 
       multi-image uploads), process customer bookings (status updates, passport 
       inspection, invoice printing), moderate reviews & guest stories (approve / 
       reject workflows), manage user roles, and read incoming contact messages.

4. BACKEND API ENDPOINTS & CONTROLLERS
===============================================================================

Authentication & Users (/api/users):
  - POST /api/users/register         -> Register new user account
  - POST /api/users/login            -> Authenticate user & return JWT token
  - GET  /api/users/profile          -> Get current user profile
  - PUT  /api/users/profile          -> Update user profile & password
  - GET  /api/users (Admin)          -> Fetch all registered users
  - PUT  /api/users/:id/role (Admin) -> Update user role (USER <-> ADMIN)
  - DELETE /api/users/:id (Admin)    -> Delete user account

Tours & Packages (/api/tours):
  - GET  /api/tours                  -> Fetch all active tour packages
  - GET  /api/tours/:id              -> Fetch specific tour details by ID
  - POST /api/tours (Admin)          -> Create new tour (supports up to 5 multi-image uploads)
  - PUT  /api/tours/:id (Admin)      -> Update tour details & images
  - DELETE /api/tours/:id (Admin)    -> Remove tour package

Bookings (/api/bookings):
  - POST /api/bookings               -> Create new tour booking (attaches global orderNumber)
  - GET  /api/bookings/mybookings    -> Fetch customer's own bookings with orderNumbers
  - GET  /api/bookings (Admin)       -> Fetch all system bookings with global orderNumbers
  - GET  /api/bookings/stats (Admin) -> Fetch summary metrics (Total, Pending, Confirmed, Cancelled)
  - PUT  /api/bookings/:id           -> Update booking dates/guests or status (Admin)
  - DELETE /api/bookings/:id         -> Cancel or delete booking

Reviews (/api/reviews & /api/public-reviews):
  - GET  /api/public-reviews         -> Fetch all APPROVED public reviews
  - POST /api/public-reviews        -> Guest submit review (status: PENDING)
  - POST /api/reviews                -> Authenticated review submission (status: PENDING)
  - GET  /api/reviews (Admin)        -> Fetch all reviews (PENDING & APPROVED)
  - PUT  /api/reviews/:id/status     -> Admin approve/reject review
  - DELETE /api/reviews/:id (Admin)  -> Delete review

Stories & Gallery (/api/blog):
  - GET  /api/blog                   -> Fetch published gallery stories
  - POST /api/blog/submit            -> Guest photo story submission (status: PENDING)
  - POST /api/blog (Admin)           -> Create admin blog post
  - PUT  /api/blog/:id (Admin)       -> Update blog post
  - DELETE /api/blog/:id (Admin)     -> Delete blog post

Contact Messages (/api/messages):
  - POST /api/messages               -> Submit contact form message
  - GET  /api/messages (Admin)       -> Read incoming contact messages
  - PUT  /api/messages/:id/read      -> Mark message as read
  - DELETE /api/messages/:id         -> Delete contact message

6. CORE FUNCTIONALITIES & WORKFLOWS
===============================================================================

1. Clean Sequential Order Numbers (#00001, #00002, ...):
   - Every booking created in the system is assigned a global sequential order ID 
     (#00001, #00002, ...) computed chronologically against database creation timestamps.
   - Preserved across Admin Orders, Admin Dashboard, and Customer My Account screens.

2. Review Moderation Workflow:
   - When a guest or customer submits a review, the backend initializes `status: "PENDING"`.
   - The review is hidden from the public Reviews page until an Admin opens the Admin Reviews 
     tab and clicks "Approve Review". Once approved (`status: "APPROVED"`), it instantly 
     renders on the public Reviews page.

3. Tour Image Carousel & Blur Background Modal Card:
   - Tour Detail view opens in a clean modal card over a blurred main background overlay.
   - Supports up to 5 package photos per tour with left/right carousel arrows and thumbnail selectors.

4. Form Password Visibility Toggle:
   - All password inputs across Login, Register, and Account Profile forms feature an interactive 
     eye icon toggle (FaEye / FaEyeSlash) allowing users to show or hide their password.

9. SETUP, DEVELOPMENT & RUNNING INSTRUCTIONS
===============================================================================

PREREQUISITES:
  - Node.js (v18 or higher)
  - npm / npx

RUNNING THE BACKEND SERVER:
  1. Open terminal in `/backend`
  2. Install dependencies: `npm install`
  3. Push database schema: `npx prisma db push`
  4. Generate Prisma Client: `npx prisma generate`
  5. Start server: `npm run dev` (Runs on http://localhost:8000)

RUNNING THE FRONTEND CLIENT:
  1. Open terminal in `/frontend`
  2. Install dependencies: `npm install`
  3. Start dev server: `npm run dev` (Runs on http://localhost:5173)
